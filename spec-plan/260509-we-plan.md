# Plan — work-experience integration

Implements `spec-plan/260509-we-spec.md`. Plan saved here per user direction (overrides the default `~/.claude/plans/...` location).

## Context

The site currently sources structured personal data from a JS object literal (`window.resume` in `assets/js/resume.js`) — except for **work experience**, which is split between:

- `assets/js/resume.json` — 8 entries, never read at runtime (the only consumer, `fetchResume.js`, is dead code with a `.then(r=>r.json())` double-parse bug).
- `index.html` `<section id="experience">` — hardcoded markup unrelated to either source, listing roles from a different person (Arizona State University, Augmenify, Epitome, Meditab, ISRO) that came in with the original `rajaprerak.github.io` template fork.
- `index.html` `<section id="portfolio">` — also leftover template content (Twitter Analysis, Music Player, etc.) the user wants to repurpose.

Goal: make work-experience consistent with how every other section already works (data in `window.resume`, rendered by a small jQuery decorator file mirroring `assets/js/education.js`). Then split it into **recent** (last 5 years, Genos onward) shown in the Experience section, and **older** (Qualysoft and earlier) shown where the Projects section is today. Once that's done, `resume.json` and `fetchResume.js` can be deleted — the user keeps a single source of truth in `resume.js`.

Existing patterns to reuse (do **not** invent new ones):
- Lazy-population pattern: `assets/js/education.js` `onEducation()` / `education2(x)` and the `#x-link` + `.mobile-nav > ul > li > a[href='#x']` dual click bind.
- `listItem(icon, category, text)` helper in `education.js:23–29` builds the `<li><i class="icofont-…"></i>category: <strong>text</strong></li>` pattern — reuse for the header row.
- `.services .icon-box` card style (`style.css`, dark blue-grey `#09203a`, hover `#042e5f`, green accent `#1c7d32`) — reuse verbatim, no new theme.
- Bootstrap 4.4.1 ships `.badge` / `.badge-pill` — used for the tech-stack pills, no custom CSS needed.

## Decisions baked into this plan (call out if any are wrong)

1. **Recent ÷ Older split**: recent = `Microsoft`, `Collectius`, `Genos`. Older = `Qualysoft (Team Lead)`, `Qualysoft @ Hoist`, `Endava @ Royal Mail`, `Endava @ eShopWorld`, `BullGuard`. Matches user's "starting with Genos" instruction.
2. **Key naming = camelCase, not PascalCase**. Spec says "pascal case", but the two authoritative examples (`storageData`, `srcTrk`) are camelCase, and every existing key in `resume.js` (`birthDate`, `baccalaureate`, etc.) is camelCase. Going with camelCase.
3. **Older-experience section name** — propose **"Heritage"** as primary (short, evocative, single word; nav reads `<span>Heritage</span>`). Alternates if rejected: `Archive`, `Track Record`, `Origins`, `Earlier`. Section ID becomes `#heritage` (replaces `#portfolio`).
4. **Sort order**: descending by end-date (most recent first). Microsoft entry's `end-date: "May 2025"` is correct; user explicitly noted "pls recheck" — verified, ordering is already correct in `resume.json`.
5. **Tech-stack array split**: simple `s.split(",").map(x => x.trim()).filter(Boolean)`. Known minor casualty: `"c# 9,10"` becomes `["c# 9", "10"]`. Acceptable per spec ("do split tech-stack strings into arrays").
6. **`fetchResume.js` fate**: deleted, not "wired up". Spec is internally clear: data moves to JS object, JSON is deleted, "reading from JSON should be cleaned up" → no JSON reader needs to exist.
7. **`projects/*.html` orphans**: not deleted in this plan (out of scope: spec only mentions deleting RJSN). Listed as follow-up cleanup at the bottom.

### `assets/js/workExperienceRecent.js` — new file (mirrors `education.js`)

```js
$("#experience-link").on("click", function () { onWorkRecent(); });
$(".mobile-nav > ul > li > a[href='#experience']").on("click", function () { onWorkRecent(); });

function onWorkRecent() {
    if (window.resume && Array.isArray(window.resume.workRecent)
        && $("#rowExperience").children().length === 0) {
        window.resume.workRecent.forEach(workCard);
    }
}

function workCard(x) { /* renders one card into #rowExperience — see UX below */ }
function pillGroup(label, items) { /* renders one tech-stack row */ }
```

`workCard(x)` builds:

1. `<div class="col-md-12 mt-4 mt-md-0 icon-box" data-aos="fade-up" data-aos-delay="100">` (matches existing `.services .icon-box` card).
2. **Header `<h4>`** — `company` as link (`x.siteUrl`, `target="_blank"`, color `#12d640` to match existing inline style).
3. **Single info row** (`<div class="row">` of `col-lg-4 col-md-6`s, one per field) using the `listItem(icon, category, text)` helper exported from `education.js` (move it to a shared spot, see below):
   - `icofont-history` → "When" → `${startDate} – ${endDate}`
   - `icofont-code` → "Position" → `position`
   - `icofont-handshake-deal` → "Collaboration" → `collaboration`
   - `icofont-tag` → "Business" → `business`
   - `icofont-link` → "Site" → `<a>` (employer link, `target="_blank"`)
4. **Description** — `<p class="mt-3" style="text-align:left">x.description</p>`.
5. **Tech-stack rows** — for each present field, one `<div class="row">` with:
   - `<div class="col-md-3"><strong>{label}</strong></div>` (label like "Language", "Database", "Tests"…)
   - `<div class="col-md-9">` containing one `<span class="badge badge-pill badge-success mr-1 mb-1">{item}</span>` per array element.
   - Field-to-label map: `language → "Language"`, `database → "Database"`, `storageData → "Storage / Data"`, `tests → "Tests"`, `srcTrk → "Source / Tracking"`, `messaging → "Messaging"`, `deployment → "Deployment"`, `logging → "Logging"`, `distributed → "Distributed"`, `infrastructure → "Infrastructure"`, `apm → "APM"`, `web → "Web"`, `webApis → "Web APIs"`, `cloud → "Cloud"`, `design → "Design"`, `misc → "Misc"`. Render in this fixed order (skip empty/undefined).

Recommendation: single `workExperienceCommon.js` loaded first, then the two thin `…Recent.js` / `…Old.js` files that just bind handlers and call `renderWork(arrayKey, rowId)`.

## Parallel execution notes

The user requested "parallel execute". Independent work units that can be split across agents:

1. **Data move agent** — edits `resume.js` only (adds `workRecent`/`workOld` arrays with normalized keys + arrays). Reads `resume.json` for content, applies the rename map.
2. **Renderer agent** — creates `workExperienceCommon.js`, `workExperienceRecent.js`, `workExperienceOld.js`. Depends on the schema decided in #1 (so brief this agent with the schema, not "wait for #1").
3. **HTML/cleanup agent** — edits `index.html` (nav, sections, script tags), edits `main.js` (comments out portfolio isotope + venobox blocks for future reuse), deletes `resume.json` / `fetchResume.js` / `certification.js`.

All three can run in parallel after the schema is decided in this plan; they touch disjoint files. Final integration step is a manual browser smoke test (verification list above).
